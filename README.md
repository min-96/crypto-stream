## 판정 기호

- **[원본]** 이미지 또는 Python 파일에서 직접 확인됨.
- **[합의]** 대화에서 사용자가 결정한 사항. 원본 구현이 그랬다는 의미는 아님.
- **[가정]** 설계를 진행하기 위한 잠정안. 변경 가능.
- **[미결]** 원본으로 확인 불가. 임의로 확정하거나 임의 값으로 채우지 않음.
- **[충돌]** 서로 다른 제공 자료 사이에 불일치가 있음.

## v0.2 대비 중요한 정정

1. 이전의 **거래소별 최신 시세 Snapshot을 매초 평균** 내는 설명을 **1초 시간 구간 동안 수집된 메시지의 평균**으로 변경한다. 다만 **전체 메시지 동일 가중(B-1)** vs **거래소별 구간 평균 후 동일 가중(B-2)**은 아직 결정되지 않았다.
2. 1초 **집계 구간(window duration)**과 1초 **실행 트리거(trigger interval)**를 구분한다. 기본값은 각각 1초이며, 6개 분석의 별도 윈도우·이동평균 기간은 미결이다.
3. v0.2에 적힌 **10초 검증 TTL, 최소 2개 거래소, 연결 끊김 즉시 제외, 최신값 재사용**은 이번 구간 평균과 자동 결합하지 않는다. 과거 설계안으로 이관하고 **현 설계의 확정 요구사항에서 제외**한다.
4. 기준 통화는 현재 **KRW 환산**을 사용하기로 한 설계 방향을 반영한다. FX 수집원/환율 시점/실제 통화 매핑은 미결이다.
5. MySQL의 6개 테이블과 `average_schema`는 **서로 다른 결과 계약**이다. `average_schema`의 저장·발행 경로는 원본 그림에 표시되지 않는다.
6. MinIO의 **데이터 축적**은 그림에서 확인되지만, 별도 오프라인 분석/재처리 Job은 그림에 없으므로 **가능한 활용 목적**으로만 적는다.
7. `average_schema = StructType(StructType([...]))`는 **원본 그대로 보존**하되, 런타임 유효성 이슈를 미결로 기록한다.

## 사용 순서

1. `01`·`02`로 시스템 경계를 확인한다.
2. `06`에서 분석 필드별 원천과 계산 가능성을 검토한다.
3. `05`와 DDL 초안으로 MySQL 결과 저장 모델을 검토한다.
4. `03`·`04`·`07`에서 미결 사항을 승인한 뒤 구현에 착수한다.
